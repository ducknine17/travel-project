# 2026-09-16 수정 사항 반영

사용자 제공 HWPX의 화면 피드백을 기준으로 작업했습니다. 사용자 확인에 따라 뼈다귀, 성장, 활동에 따른 강아지 해금은 이번 범위에서 제외했습니다.

## 반영 사항

- 둘러보기·지도: 장소 종류 7개와 펼쳐보는 편의시설 5개 그룹. 검색·복수 시설·분류를 함께 적용하고 초기화 가능.
- 글쓰기: 장소 종류 선택과 동일한 편의시설 그룹, 항목별 별점. 기존 이모지 태그와 별점도 계속 인식.
- 지도: 필터 옆에 여행지 목록 배치, 모바일 필터 접기. 목록과 핀에서 동일한 장소 상세 열기.
- 장소 상세: 주소, 소개, 문의, 편의시설 설명, 제공 사진·리뷰 사진, 연결 리뷰, 외부 지도, 해당 장소 글쓰기 링크. 제공되지 않는 정보와 조회 실패를 명시.
- 책갈피: 발바닥을 하트 중앙으로 이동. 상세 글 상단에 회청색 수첩 선 추가. 글 제목에 나눔명조 적용.
- 지도 아이콘: 두 번째 핀 시안을 바탕으로 하트 핀, 버스 정류장, 일반·저상 버스 SVG 구성.
- 가방: 꾸미기 버튼 강조, 배지첩에서 강아지 선택 진입, 모자·고글·여행 도구를 캐릭터와 가방에 상대 위치로 장착. 기존 스카프 설정은 고글로 이전.
- 프로필: 사용자 사진과 표시 이름 저장 API 및 편집 UI. 이메일형 ID는 기본 표시에서 도메인을 제외. 계정 아이디와 글 소유권은 유지.
- 강아지 선택은 가방 꾸미기에서 제공. 친구 이름·배지·아이템은 기존 가방 설정과 동일하게 브라우저에 저장하고, 강아지 종류는 기존 서버 API로 저장.

## 배포 전 적용 사항

1. `backend/sql/add_user_profile.sql`을 DB에 적용한 뒤 백엔드·프런트엔드를 함께 배포합니다. 이번 작업에서는 운영 DB 변경이나 배포를 실행하지 않았습니다.
2. 한국관광공사 `KorWithService2/detailCommon2`, `detailWithTour2`의 접근 권한·서비스 키·서버 연결을 확인합니다. 현재 개발 환경의 실제 요청은 두 경로 모두 HTTP 403이었습니다. 실패 시 기본 장소와 리뷰를 유지하며, 상세 조회에는 시간 제한과 짧은 실패 캐시를 적용했습니다.
3. 미리보기 브라우저에서는 카카오 지도 SDK가 준비되지 않아 실제 지도 타일·실시간 버스의 시각 검증은 수행하지 못했습니다. 마커 클릭·정류장 확대 조건·차량 좌표 전달은 SDK 모의 객체를 이용한 테스트로 검증했습니다.

## 데이터 제약

- 기존 장소 DB에는 `tour`, `culture`, `food` 등 넓은 분류만 있어 바다·공원·카페의 세부 분류는 이름을 바탕으로 보완합니다. 완전한 분류를 위해서는 원본 관광 분류코드 적재가 필요합니다. 새 글의 명시적 분류는 우선 적용합니다.
- 장소-리뷰 연결은 기존 서버 구현의 장소명 일치 기준을 유지합니다. 같은 이름의 다른 장소를 완전히 구분하려면 게시글에 장소 ID를 저장하는 별도 데이터 이전이 필요합니다.
- 캐릭터 장착물은 기존 SVG 아이콘 체계를 사용한 구현이며, 문서 안의 일러스트 원본을 투명 이미지로 재가공하지 않았습니다.

## 검증

- 프런트엔드: 12개 테스트 묶음, 총 24개 통과.
- 백엔드: 총 40개 테스트 통과. 모의 DB·외부 API를 사용하므로 운영 데이터에 쓰지 않습니다.
- `npm run build:local` 통과.
- 브라우저: 둘러보기, 장소 사진·리뷰 상세, 모자·고글 장착, 프로필 이름 저장 확인. 390px 모바일 지도에서 접힌 필터, 목록 노출, 가로 넘침 없음 확인.
- 로컬 미리보기: `frontend`에서 `npm run start:preview`. 예시 데이터 전용이며 운영 서버에 저장하지 않습니다.
